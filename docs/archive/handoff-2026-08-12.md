## Hard-won things worth not relearning

**Do not assert expected numbers in an agent brief unless you have re-derived them.** I told
a splitter agent the 3" nose was "2 pieces on an H2D, 3 on an MK4S". The 3 came from a design
doc's 25 mm spigot estimate, where the implemented `spigotLengthFor()` gives 19.05 mm on a
Ø76.2 part. The agent could not reach 3 honestly, so it made `usableBox()` take the margin
off Z *twice* to force it — and said so plainly in its report, which is the only reason it
was caught. X and Y correctly lose 2× the margin (inset from both bed edges); Z loses it
once, because a part sits ON the bed at z = 0. Corrected: H2D usable Z is **317 mm**, the 3"
nose is **2 pieces on both** machines, and the headline reads "64 mm too long", not 72.
`usableBox` is now **exported** and the tests derive from it — 17 tests had pinned the old
value. An agent will fit the model to your assertion; give it the derivation, not the answer.

**Eric's CSS blocks are written against `chrome.ref.js`'s markup, not ours.** Our band is
React and renders bare `<a>` (no `<ul>/<li>`), and `.mmr-band-search` **is** the `<form>`
rather than wrapping one. Pasted verbatim, `.mmr-band-nav li` and `.mmr-band-search form`
are both silent no-ops — and the second would have left the 130px search input visible at
375px. Translate them and comment each with the reference selector it corresponds to.
Spec §5 explicitly leaves the JSX to each tool, so this is expected, not a defect.

**The splitter is cheap only because of one architectural fact.** Every revolved printable
part comes from ONE closed `(x, r)` loop via `bodyLoop()` → `revolveProfile()`. Splitting is
half-plane polygon clipping plus a generated spigot, then re-revolving — so each segment
inherits `revolveProfile()`'s watertightness proof by construction. **Never reach for a mesh
boolean or a CSG library here**; the moment someone does, the cost triples.

**The spigot is a running MINIMUM of the bore, not an offset of it.** A nose bore widens aft,
so a straight offset copy is fatter at its tip than the socket mouth and cannot enter at all.

**Cuts are legal only inside the body span.** `bodyLoop()` doubles back inside shoulder
spans, and clipping there emits a zero-width bridge — a non-manifold STL that Bambu Studio
will silently "repair" into something wrong.

**Environmental, unchanged since v0.041:** the R3F canvas never initialises under this CDP
browser, so 3D features cannot be click-verified here. The auto-fit framing maths is covered
by 25 unit tests against hand-derived numbers instead (including a real `PerspectiveCamera`
projection check that all eight bounding-box corners land inside NDC), but Eric should click
it once. Do not try the rAF→setTimeout monkeypatch — it breaks R3F mounting.

**Adversarial verification earned its keep again.** Across three workflows (13 agents) the
verifiers found **16 real defects** pre-release, including: the auto-fit framed stubby
rockets *smaller* than doing nothing; the lean check certified a placement against the bed
*diagonal* while ignoring part width; a solid part's stub and socket were cut to identical
lengths, hydraulically trapping the epoxy the README instructs you to use; and a `parseNav`
case where one legal site-side edit (an empty `footer.links`) would have pinned this tool to
its offline fallback permanently and silently. Keep doing this.
