- **#2 Power-on vs power-off drag** (commit `39f0601`). Per-stage
  `nozzleExitDiameter` (m). Model chosen (no published formula exists —

  `AbstractSimulationStepper.applyThrustState` from `status.getActiveMotors()`),
  `BarrowmanCalculator.calculateBaseCD` subtracts nozzle area when
  `isStageThrusting(stage#)`. `.ork`: `<nozzleexitdiameter>` per stage (only
  emitted when >0).
- **#5 Drag analysis panel** (commit `fd38e11`). Bridge `getDragSweep(handle,
  optionsJson)` → per-Mach total/friction/pressure/base CD for BOTH power
  states + per-component power-off breakdown. App `DragPanel.tsx` (uPlot, same
  idiom as FlightCharts): collapsed by default (sweep only computed while
  open), power-on curve dashed and only when a nozzle is set, By-component /
  By-type toggle, Max-Mach 1/2/3/5, CSV. Honesty label: >~Mach 1.5 values are
  Extended-Barrowman estimates (until #1).

  Kfb=(1+τ) to fins; slender-body total is (1+τ)², so the missing body load is

  conservative). New patch `FinSetCalc.java` + flag threaded from
  `BarrowmanCalculator.setRogersKbf` at calcMap build; bridge
  `setRogersModifiedBarrowman(handle, bool)` applied in BOTH getStaticInfo and
  simulateJson so displayed CP and flight agree.

## 3. Decisions Eric made this session (do not re-litigate)

1. **#1 approach: REPLICATE RASAero's semi-empirical method in-kernel** (not
   bridge/PANAIR — PANAIR can't do transonic and breaks the one-embeddable-
   artifact invariant). #2/#3/#5 are the first bricks of #1, not throwaways.
2. **Validation baseline: RASAero published outputs + ARCAS wind-tunnel PDFs
   only** (no independent flight telemetry available). Treat as directional —
   RASAero's accuracy numbers are vendor-self-published.
3. **#2 drag model: plume-neutralization** (geometric, no fudge factor) over a
   tunable calibration constant.
4. **Nozzle exit diameter lives per-STAGE** (matches RASAero's data model) —
   later independently confirmed by research: RASAero stores it per stage in
   .CDX1; it has NO motor-mount concept at all.
5. **#3 scope: Kbf only.** The other two Rogers terms deferred deliberately:
   (a) low-α nose→body lift carryover — exact Rogers formula is UNPUBLISHED
   (semi-empirical/proprietary); (b) Jorgensen crossflow — OpenRocket's Galejs
   body-lift term IS already a ∝sin²α crossflow with fixed k=1.1 (see the
   memory file `openrocket-galejs-is-crossflow`); upgrading it needs RASAero's
   proprietary DATCOM-modified Cd_c table and risks perturbing a tuned term.
   Both belong to the #1 conversation.
6. **Body-tube mounts: allow ANY body tube, no blocking validation** — Eric's
   instinct, confirmed by 25/25 adversarially-verified research claims: no
   surveyed tool (OpenRocket desktop, RASAero) blocks or validates this; fit
   checks are advisory-only (our motor browser already filters by mount
   diameter, which works generically).

## 4. Research artifacts (3 workflow passes this session)

- **Base-drag extraction** (from the PDFs Eric put in `docs/`): the RASAero
  Manual + Rogers&Cooper describe the power-on mechanism but publish NO
  formula. ARCAS PDF yields EXACT validation anchors (§5). Regime breakpoints:
  subsonic ≤0.90, transonic 0.91–1.04, supersonic-hypersonic 1.05–25;
  transonic drag rise onset ~Mach 0.90.
- **CP/Kbf equations** (open literature, primary NASA sources): NACA 1307
  gives closed-form K_W(B) (Eq. 14) and the identity K_W(B)+K_B(W)=(1+λ)²;
  Jorgensen TR R-474 gives CN = (Ab/Ar)·sin2α'·cos(α'/2) + η·Cdn·(Ap/Ar)·sin²α'
  — useful for #1. Kernel map: fin body-interference is `FinSetCalc` ~line 154
  (`cna *= 1+tau`, with the `(1+τ)²` thesis form commented out beside it).
- **Min-diameter deep research** (103 agents, 25/25 confirmed, 0 refuted):
  validated the body-tube-mount fix on every point; surfaced overhang (now
  built); noted "sub-minimum" designs (fins on motor case — model as a body
  tube with case dimensions; now in the guide). Open question parked: RockSim's
  own mount model was never verified (we handle .rkt pragmatically).

Full research reports live in this session's workflow journals (temp dirs, may

## 8. Nuances & gotchas learned this session (save these)

- **LEDGER.md now has a "Feature patches" section** — deliberate physics
  EXTENSIONS (default-off) vs the TeaVM shims. Rule 1 was amended accordingly.
  Every feature patch must stay default-off ⇒ flag-off is bit-identical.
- **Deploy verification protocol that works**: fetch `./?cb=<ts>` with
  `cache:'no-store'` from a page on the site, regex the `assets/index-*.js`
  hash out of the served HTML, compare to local `dist/index.html`, then grep
  the served JS for new feature strings. The SW-cached badge alone can lie.
- **Guide mirrors**: `docs/user-guide.md` AND `packages/app/src/data/userGuide.ts`
  must be edited together. The .ts strings use HTML entities (&mdash; &tau;
  &quot;) and literal `\n` (backslash-n) separators — match small unique
  substrings when editing. The guide had gone stale for 6 versions before this
  session; **update it as part of each feature, not in arrears** (Eric asked).
- **Eric's cadence this session**: "build in recommended order, only pause for
  needed input" — he answered scope/model questions crisply when asked
  (AskUserQuestion with a recommended option works well). He deploys manually
  and says "live site is updated"; verify immediately. He deleted a deploy zip
  by accident once — `npm run package` regenerates it identically.
- **Version flow**: bump + changelog when packaging a release; a not-yet-
  uploaded version can be refreshed in place (v0.023 was packaged, then
  extended with overhang and repackaged under the same number before upload).
- **AskUserQuestion note**: Eric sometimes answers "Other" with a directive
  (e.g. "ultracode go ahead and start the build...") — treat the text as the
  real instruction, not the option list.
- **Workflows**: deep-research (103 agents) is expensive but its adversarial
  verification caught nothing wrong — the cheap 4–5-agent Understand fan-outs
  (PDF extraction + kernel mapping) gave the highest value per token. PDF
  agents need the "pages required, ≤20/call, use pdftotext" coaching in the
  prompt.
- **jq/grep on this box**: watch the working directory — a `cd engine-java`
  inside one Bash call persists to the next.
