## 5. Nuances & gotchas (hard-won this session — do not relearn)

- **PowerShell mangles UTF-8** (hit 3×; memory file
  `powershell-utf8-mangling.md`): `(Get-Content -Raw) -replace |
  Set-Content` → mojibake; `git show | Set-Content` → collapsed newlines.
  Edit non-ASCII files ONLY with Edit/Write tools; restore with
  `git checkout <commit> -- <path>`.
- **Occluded-window browser testing**: monkeypatch
  `window.requestAnimationFrame = (cb) => setTimeout(() => cb(performance.now()), 33)`
  in the page — sims run headlessly. **33 ms, not 0** (0 spins the CPU and
  freezes the renderer). Screenshots often time out once then succeed.
- **Forcing app state for tests**: edit the session/prefs JSON in
  localStorage + reload beats fighting NumField DOM commits (React needs
  native-setter + input event + Enter keydown, and even then it's flaky).
  Always back up `online-openrocket.{session,sim-runs,prefs}.v1` first,
  restore + remove `workspace.v1` after.
- **Kernel model iteration**: prototype in a scratchpad JS mirror against
  the anchors FIRST (one TeaVM rebuild instead of twenty). The Phase-1
  prototype pattern is in the session history; rebuild loop is ~30 s.
- **Multi-line commit messages**: here-strings in compound commands fail
  silently — ALWAYS write to a scratchpad file + `git commit -F` (this is
  old advice; it bit again this session).
- **Guide mirrors**: docs/user-guide.md AND packages/app/src/data/
  userGuide.ts must be edited together (ts uses HTML entities + literal \n).
- **Deploy verification protocol**: from a page on the site, fetch
  `./?cb=` with `cache:'no-store'`, regex the served bundle hash, compare
  to local dist/index.html, grep served JS/CSS for feature strings. Now
  also: fetch `./version.json` and confirm the payload.
- **rogersKbf is superseded** by supersonicAero when that flag is on
  (1307 contains the full carryover — the FinSetCalc code guards this).
- The vitals strip mass/apogee values use UnitChip — any new strip station
  showing a unit must too (Eric's rule).
- **styles.css wide-screen block must stay LAST in the file** (it says so
  in a comment). The overrides share specificity with the base rules, so
  source order decides — a mid-file `@media (min-width: 1600px)` block
  silently lost to later base rules (caught on `.stat-row` in v0.030).
  Any new base rule that a wide override targets must be added ABOVE it.
