# Issues 2026-08-05e

- I like the new fin rotation capability. For users building these kinds of fins on a new rocket, there should be button that says something like "auto-align multiple fin sets" or something to that effect so they don't have to manually rotate fins to get them into the perfect alignment.
- in the tube fins dialogue when adding new fins, if i leave either fin count or outer diameter blank, the app will auto populate and limit the other setting. For example, if I set the number of tube fins to 6 on a 98mm body tube, it won't let me choose a diamter that doesn't fit. however, if i manually type in something in both fields, then the sliders will allow me to push past the limit where the tube fins will collide. This is a niche edge case, I understand, but the limiting factors should still be  in place to ensure the fins aren't allowed to collide
- A related issue - if I just input the fin count, the tube fin outer diameter box stays blank. This is a problem because, in the design phase, the user may try out as number of configurations, but, ultimately, will need to know what the diamter of the tube fin is in order to actually build it on a real rocket. This is probably a case where the autopopulated number is grayed until the user does or does not override it
- for files imported from Rocksim that have a component labelled "Camera shroud" or "shroud", can you add a prompt for the user that says "it looks like your file has a camera shroud, do you want me to convert it to a native camera shroud in this app" or something like that. And then, the app autoii converts it without the need for the user to do anything. That would be the best workflow
- A missing feature (or, one I can't find right now) is the ability to make a sub-minimum diameter rocket. Right now we can make a minimum diameter rocket (just make the outer body tube a motor tube), but I can't find a way to make a sub-minimum diamter rocket. A sub-minimum diamter rocket is one where the motor case is the outside diameter of the rocket. This is a common use-case in very high performance flights (the exact ones we added all the high mach math for). For the purposes of this app, you don't need to understand the process of making a subminimum rocket, but i will quickly explain some of the ways it is done do you have context. In some cases, people mix and cast the solid motor fuel directly into a tube that will become the outer diameter of the rocket. In this case, the rocket becomes the motor. this is often done with non-standard motor sizes. IN other cases, people adhere fins directly to a commercial motor case. In this case, the motor becomes the rocket. Since this is a common practice for very high performance, high mach flights, we need a way for users to model this.
- When choosing motors, we also need to give users a way to import non-commercial motors. These kinds of motors are often called experimental (EX) or research motors. Generally. people model their motors in other tools (like the motor sim tool I am building separately) and then save the EX motor as RASP (.eng) motor file or a Rocksim (.rse) motor file. We need to be able to import eng and rse files for use in the launch page. Ideally, users can import a discreet file for single use or they could do something like establsh a folder on their computer where they store EX motor files and the app adds those stored EX files to the "browse motor database" option
