# OpenRocket Online — Notes & Feature Requests
**Date:** 3 July 2026

## UI / General Behavior
- Fins currently default to "top of parent" — should default to **"bottom of parent"**.
- App currently loads a sample rocket on start. This is fine, but add a **"clear all components"** button to let users start from scratch.
- All component attributes should have a **slider** to dynamically adjust values:
  - Sliding should update the number in the input box in real time.
  - The visual preview should update accordingly in real time.
- When sliding the location for **internal components**, they should **snap to logical positions** (e.g., centering rings should snap to the ends of internal fin tabs, since that's where they're installed in the real world).
- Ideally, component location should be **draggable directly in the visual preview**.
- On the main screen visual depiction, the user should be able to see:
  - Overall length
  - Maximum diameter
  - Mass with no motors
  - Mass with motor loaded
  - Which motor is currently loaded
  - Exact measurements for CP and CG (including CG "dry" and with motor loaded)
  - Stability, shown as both **caliber** and **percentage**

## Units of Measure & Preferences
- Need the ability to **switch units of measure**, with granular control per aspect of the rocket (e.g., inches for the rocket structure, mm for the motor tube). Reference the OpenRocket desktop app for the correct level of granularity — ask if unclear.
- For all round components, the app currently uses **radius**; users are more familiar with **diameter**. Add a preference to choose radius or diameter as the input method.
- Need an overall **Preferences menu** covering:
  - Units of measure
  - UI theme (e.g., dark mode)
  - Other settings — review the desktop app's full Preferences dialog to determine full scope

## Component Attributes (All Components)
- Add ability to input **overrides** for:
  - Exact mass (real-world material mass varies significantly)
  - Center of gravity
  - Coefficient of drag (Cd)
- Add **appearance** customization: color, texture, etc. (available in desktop app).
- Add **material** selection — helps estimate weight and CG. Desktop app has a database for this; import and use it.
- Add **finish** setting (e.g., unfinished, regular paint, matte, gloss, polished). This significantly affects Cd. Desktop app has a database of finish options with corresponding Cd values — use them.

## Component Databases
- Import the desktop app's extensive **preset component database** for every component type; make available as dropdowns when adding new components.
- All databases (materials, finishes, presets, parachutes, etc.) should be **user-editable** within the app — ideally with a view to browse and edit databases directly.
- Support **external editing**: allow exporting a database to CSV, editing it, and re-uploading the modified CSV.
- *(Note: no need to keep flagging individual databases going forward — all components in the desktop app have associated databases, and the online app should use them across the board.)*
- General ask: review all component attributes available in the desktop app and identify what's missing from the online app — most attributes are currently missing and it's time-consuming to audit each component individually.

## Nosecone-Specific Features
- Add a **shoulder** attribute (present in desktop app):
  - Should support "snap to inner diameter" of the adjacent body tube.
- Add **shape profile** selection (e.g., ogive, etc.) — present in desktop app, missing online.
- Add **base length** attribute: the straight section at the base of the nosecone before the curved shape begins. Not in the desktop app, but a real-world attribute that affects CP and should be included.
- Add a **"solid"** option for nosecones (many real-world nosecones are solid). Combined with material selection, this would significantly affect calculated weight and CG.

## Flight Simulation / Events
- Add support for **flight events**, e.g.:
  - Drogue parachute deployment at apogee
  - Main parachute deployment at a set altitude
  - In the desktop app, this is configured via the parachute component's **"deployment"** setting.
- Import the desktop app's **parachute preset database** and make it available to users.
