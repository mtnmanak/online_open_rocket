# OpenRocket Online — Test Run Notes
**Date:** 3 July 2026

## General

### Blockers
*(none noted)*

### Annoying
- The current session should be **stored and restored** if a user closes the browser window and comes back. This solves the problem of a user inadvertently closing the window without saving the ORK file, or the browser crashing before the file is saved.
- When saving the ORK file, the **rocket name** should be the default filename.
- When importing an ORK file, the ORK format includes a "rocket name," but it doesn't currently get imported — imported rockets show as "Rocket" instead of the actual name.
- When the user clicks **"New"** to clear the data, they should get a warning that this will clear all data and a prompt to make sure they've saved the ORK file before proceeding. Offer to save the file first.

### Cosmetic
- Decimal places can be **capped at 3** for display purposes only (the full precision number should still be stored for calculations). Round up or down as appropriate.

### Features
- Need to be able to import **user-created motor files** in RASP (`.eng`) or RockSim (`.eng`) formats to accommodate experimental (EX) motors.
  - Once a user imports an EX motor, it should be added to an internal app database for later use.
  - In the motor picker dialog, **"EX"** should appear as an option under "Manufacturer" if an EX motor exists in that motor class.
- **Launch results need significantly more data.** Expected data attributes after a launch simulation:
  - Simulation
  - Engine diameter(s) (mm)
  - Results
  - Altitude at deployment
  - Engines loaded
  - Max. altitude
  - Max. velocity
  - Time to apogee
  - Time to burnout
  - Velocity at deployment
  - Velocity at launch guide departure
  - Thrust to weight ratio at launch guide departure
  - Optimal delay
  - Max. acceleration
  - Weathercocking
  - Lift off speed
  - Ninety degree safety
  - Static margin safety
  - Recommended delay
  - RockSim recommended
  - Safe deployment
  - Comments
  - Execution time
  - Total flight time
  - Time to launch guide departure
  - Launch mass
  - Launch CG
  - Launch CP
  - Launch static margin
  - Manufacturer(s)
- **Launch simulations should be stored and listed** after each run so a user can download results as a CSV. This is important since users will simulate many motors and want to compare/store results to choose a motor for a given flight day.
- Need a way to **batch-simulate motors**:
  - Upload/select a batch of motors to simulate at once (e.g., 100 candidate motors), rather than simulating one at a time.
  - Alternative: a "simulate all motors that fit this rocket" option, with filter criteria to exclude unsuitable motors — e.g., minimum thrust-to-weight ratio, min/max apogee, velocity at launch guide departure threshold, etc.
  - Output should be a downloadable list of simulation results.
 - Rocksim materials and parts data. I added all the CSV files that RockSim uses for parts and materials to a folder in docs called "materials". Compare the data in those files to the ones in our current parts and materials database from OpenRocket. If any information is the same, use the OpenRocket data. If any of the information from the Rocksim files is new, add it to our available database. For any discrepancies use your best judgement or ask me if there is any serious conflict

## Wildman Wild Child Rocket

### Blockers
- No option for fins to have **fin tabs** — tabs that extend through the body tube wall into the rocket interior. Fin tabs are important to real builds and affect fin weight/CG.
  - Fin tab depth should default to just touching the motor tube (as in real rockets).
  - Fin tabs should provide **snap-to positioning** for centering rings.
- When inputting offset/location values: clearing the field and typing a number resets to "0," and typing a negative sign directly doesn't work. Currently, to enter a negative value, the user must use the arrows to click down into negative territory, then edit the number without deleting the negative sign. **Users should be able to type any number directly**, including negatives.
- Are there any **type/value validation checks** currently in place? For example, in the "Thickness" field, it's currently possible to enter a letter (e.g., "e") or a negative value — both should trigger a validation error.
- The program needs to calculate an **optimal delay** for a given motor/rocket combination. Options:
  - Run the simulation, get the delay value, then re-run with that delay, **or**
  - Add an option in the "delay" dropdown for the simulation to auto-calculate the optimal delay (rounded to the nearest whole second) and run with that value.
  - This is critical — an incorrect delay can cause the rocket to crash or be destroyed in flight.

### Annoying
- For all components, the user should be able to input **either wall thickness or inner diameter**, with the other value updating automatically.
- Ability to change the **"finish"** of all components at once, while still retaining the ability to edit each component individually.
- When working on a component, the display should show attributes for **both that component and the whole rocket** at once. For example, when editing the nosecone, show length/weight/CG for both the nosecone and the overall rocket. Possibly a second visualization window for the component being edited.
- When adding components, add two buttons:
  - **"Add component to [selected component]"**
  - **"Add component to Rocket"** (appends to the next item in the list)
  - This saves time by letting users keep adding components without repeatedly clicking the rocket name at the top of the list.
- When adding a new component, it should **default to the specs of the previous component**. For example, a body tube added after a nosecone should default to the OD/ID of the nosecone base; material and finish should also default to the previous component's settings.
- Ability to **copy and paste components** in the list to save time with similar components.
- Components that slide internally into other components (nosecone shoulders, couplers, etc.) should be **visible in the display** — e.g., via a dotted outline style or similar.
- **Override boxes** should show the calculated value until/unless the user manually overrides it.
- When inputting values into the freeform finset chart, the corresponding **dot on the chart should be highlighted** in the visual display (in addition to the numeric values).

### Cosmetic
- Color picker should include **quick presets** for basic colors (white, black, primary colors, etc.).
- The rocket in 2D visualization mode extends beyond the field of view. Add the ability to **zoom and pan** the view, plus a **"Reset View"** button to bring the whole rocket back into frame.
- If a tube is designated as a motor tube, default its name to **"Motor Mount Tube."**
