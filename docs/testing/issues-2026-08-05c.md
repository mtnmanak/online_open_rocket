- **Mixed-motor combination batching (deeper question) — feasible; here's the honest cost.** The possible iterations do not explode as quickly as you may think. Remember that all motor selections in a cluster must be symmetrical. For example, in a two-motor cluster, both motors must always be the same (two different motors would be asymmetrical and cause the flight to veer off to one side). Similarly, all motors must be the same in a 3-motor cluster, since there is no combination of different motors that would be symmetrical. A 4-motor cluster is the first cluster that could have different motors in pairs. From there, only even numbers of motors could possibly be symmetrical. I think we could cap the "different motor" scenarios to 4-motor clusters and 6-motor clusters and inform the user that anything larger would not be feasible. Let me know what you think before making changes. I think we can leave airstarting out of the batch processing as well - if users want to simulate air starts, they are probably looking at very specific motor combinations and can just use the normal motor setup and launch dialogue to handle that.
- Speaking of batch motor processing, should we have a pulldown in the batch motor dialogue to let the user choose the physics model? I am thinking that "auto" would be a great choice for batch processing since some motors would result in flights well below Mach 1.0 and some may go way above Mach 1.0. It would seem counterproductive to use a single model across a batch set of motors, but it may be nice for the user to decide.
- For exporting options, should we add Excel (xlsx) as an option? I know CSVs are universal and can be easily imported into spreadsheets, but having an xlsx option would allow us to provide some formatting in the output file and to allow us to choose what kind of data lives in a cell so it displays correctly in a spreadsheet - sometimes apps like Excel will misinterpret text or integers or floats and try to convert them to dates, for example, upon import. Having an xlsx export would give the user a definitively formatted doc that would not be misinterpreted in Excel or Google Sheets. Give me your recommendation.
